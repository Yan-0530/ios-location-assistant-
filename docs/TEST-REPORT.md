# 虚拟定位助手 0.3 测试记录

[English report](TEST-REPORT.en.md) · [使用说明](../README.md)

2026 年 11 月 25 日，Windows 11 x64。后台使用 Python 3.14.7 和 pymobiledevice3 11.63.1。连接设备为 iPhone 14 Pro，系统版本为 iOS 26.7.1。

0.2 的实机检查走到了开发者服务：电脑通过 USB 找到手机，读到了型号和 iOS 版本，又通过用户空间隧道完成了一次只读 DVT 请求。到这里能确认电脑确实连通了手机的开发者服务。手机地图上的模拟位置和恢复位置还没有纳入这次实测。

## 0.3 界面复测

在 Windows 的 150% 缩放下启动新版 EXE，系统报告窗口 DPI 为 144，进程采用 Per-Monitor V2 模式。界面按设备像素绘制。中英文截图均取自运行中的窗口，尚未在两台不同缩放比例的物理显示器之间移动复测。

旧地图的高度固定为 112 像素，宽度随窗口变化。新版使用 2:1 等距圆柱投影视口，绘图和取点共用坐标变换。自动检查在画布上依次触发按下、拖动和松开，选到南纬、西经的自定义位置。坐标误差在半个地图像素对应的角度内，过程中没有派发设备命令。

在同一页面切到英文再切回中文，页面、目标经纬度均保留。英文界面的公网查询仍先弹出授权提示，取消后没有发起请求。最新版的 GUI、后端及交互检查共 15 项，全部通过。本轮没有改变实体手机的位置。

## 关于定位命令的证据

早期 PowerShell 记录包含东京（35.6812, 139.7671）、洛杉矶（34.0528, -118.2516）和一次清除命令。记录能确认当时调用了哪些命令，当时没有留下可核对的手机地图结果。

桌面程序沿用了这组命令。对 iOS 17 及以后，启动模拟后需要保留子进程，停止时先结束会话，再向原设备发清除命令。自动测试用一个等待输入的本地进程检查这段流程。另一个测试让清除命令返回错误，检查程序是否保留恢复标记。两项测试都没有改动手机位置。

旧版系统只验证了命令分流。iOS 16 及以前走传统 USB 服务；iOS 17.0–17.3 指向已运行的 tunneld；从 17.4 起选择用户空间隧道。不同机型上的驱动和开发者服务仍可能影响结果。[上游命令示例](https://github.com/doronz88/pymobiledevice3/blob/master/docs/guides/cli-recipes.md) · [上游隧道文档](https://github.com/doronz88/pymobiledevice3/blob/master/docs/guides/ios17-tunnels.md)

## 下一次真机测试怎么记

先在手机地图确认当前位置，选东京或洛杉矶，点「开始静态定位」。记录手机第一次显示目标城市所用的时间。保持 USB 连接五分钟，再请求一次位置。最后点「停止并恢复真实定位」，看手机何时回到测试前所在的区域。

报告里写机型、iOS 版本、目标城市、两次定位结果和恢复用时即可。如果恢复失败，再记录重连后重试的结果。具体住址、设备名和设备标识都不需要公开。
